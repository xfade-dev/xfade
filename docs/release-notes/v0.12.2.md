# xfade v0.12.2

**Release Focus**: Manage providers and global defaults directly from the TUI.

Bare `xfade` opens the TUI, but it previously could not add a provider — an empty list just told you to run `xfade add`. This patch closes that gap and makes the CLI and TUI create providers through the same code path.

---

## What's New in v0.12.2

### 1. Add, Edit and Remove Providers in the TUI
| Key | Action |
| :-- | :-- |
| `a` | Add a provider for the current tool (ID, Base URL, Model, API Key, Protocol, Official) |
| `e` | Edit the selected provider |
| `d` | Remove the selected provider (`y` confirms; `n`, `Esc` or `Enter` cancels). The active provider cannot be removed |
| `g` | Edit global defaults |

- Blank fields in the add form show the global default that will be applied, e.g. `(blank = global: https://gw.example)`.
- A blank Base URL with no global default is rejected unless **Official** is ticked, so you never get an official-login provider by accident.
- Adding an ID that already exists is rejected; use `e` to edit it.
- Forms scroll with the focused field on short terminals.

### 2. Global Defaults (`g`)
Equivalent to `xfade config`: secrets backend, base URL, model, API type and global API key.

> Global defaults are **copied into providers when they are created**. Changing them later does not change existing providers.

Switching the secrets backend takes effect after restart. Until then the TUI refuses to store a global API key, because it would go to the old backend.

### 3. Consistent Creation Rules
`xfade add` and the TUI now share `Core::add_provider_from_input`:
- An explicit `--official` / Official provider never inherits the global model or API type.
- Base URL and API key input is trimmed; a whitespace-only key falls back to the global key.
- `xfade add` still overwrites an existing provider with the same name (unchanged); the TUI does not.
- Interactive `xfade add` prompts for the key again; the global key fallback is for non-interactive use.

### 4. Security: dependency update
`url` 2.5.8 → 2.5.9 fixes RUSTSEC-2026-0592 (stack overflow on deeply nested `blob:` URLs). `cargo deny check` is clean.

## Upgrade Instructions

### Homebrew (macOS & Linux)
```bash
brew update && brew upgrade xfade-dev/xfade/xfade
```

### One-Line Script
```bash
curl -fsSL https://xfade.sh | sh
```

### Self-Update
```bash
xfade self-update
```

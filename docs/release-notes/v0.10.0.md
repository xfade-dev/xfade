# xfade v0.10.0

Two upstreams, one route list. This release makes heterogeneous providers work together and closes the defects found while testing that setup on real machines.

---

## Per-provider model overrides

`--model` was a single global value applied to every route. That breaks as soon as your upstreams have disjoint model catalogs — a local gateway that only knows `z-ai/glm-5.3-flash` and a cloud router that only knows `auto/best-fast` cannot both be in the same failover chain, because one of them inevitably receives a model it rejects.

`--route-model <id>=<model>` pins a model per provider:

```bash
xfade proxy use freebuff omni \
  --route-model freebuff=z-ai/glm-5.3-flash \
  --route-model omni=auto/best-fast \
  --target chat
```

- Repeatable, one entry per route.
- `--model M` remains the global fallback for any route without an explicit entry.
- `xfade proxy status` prints the map:

```text
route models:
  freebuff = z-ai/glm-5.3-flash
  omni = auto/best-fast
```

Resolution happens per `RouteEntry` after the router plans, so Smart Fader ordering, circuit breakers and failover all keep working unchanged. GUI saves (which use the legacy `set_routes` path) do not erase CLI-configured route models — the new column is written with a column-scoped UPSERT.

## Configurable 4xx failover

Previously only transport errors, `429` and `5xx` triggered failover. A `401` or a `400 model_not_allowed` stopped the chain — exactly the failure you get when an upstream does not recognise a model.

```bash
xfade proxy failover-4xx on|off     # off by default
```

With the toggle on, failover additionally fires on **narrow** 4xx responses:

- `401` / `403` (auth / permission)
- `400` model-rejection responses: `model_not_allowed`, or "model … not in / not allowed / not found"

Generic `400` / `404` / `422` still pass straight through to the client — a malformed request is not an upstream outage, and should not be silently rerouted. Transport errors, `429` and `5xx` always fail over regardless of this setting.

## Fixes

- **Duplicate `message_start`**: streaming `/v1/messages` emitted `message_start` twice when the first upstream chunk was empty. The guard was `phase == Initial`, but an empty chunk never advances the phase. A dedicated `started` flag now drives the event; `Initial` is kept only for lazily opening text/tool content blocks.
- **Docs / CLI alignment**: removed flags that never existed (`--routes`, `--model-override`, `--target-protocol`, `xfade current --tool <t>`, `xfade serve --foreground`) and comma-separated route names (`kimi,bak`) across both READMEs and the `docs/` set. `docs/api.md` documents both new features.

## Compatibility

The DB migration adds two columns (`route_models`, `failover_4xx`) with guarded `ALTER TABLE` statements. Both toggles survive `clear_routes`. No config changes are needed to upgrade; existing routes keep their global `--model` behaviour.

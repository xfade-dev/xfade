# xfade v0.9.0

Three headline features — **instant-launch subcommands** (`xfade <tool>`), a unified **session view**, and the **Smart Fader** (intent-aware tiered routing, off by default). Plus an injection layer that makes codex and opencode work with one-off launches, and a project analyzer with real consumers.

---

## New

### Instant launch — `xfade <tool>`

The tool name is now a subcommand (shorthand for `xfade run`). The provider is
resolved on the spot; all overrides are one-off and never touch the tool's
on-disk config:

```bash
xfade claude kimi -- --print                  # env injection (claude/aider)
xfade codex glm --model glm-5-2-260617        # -c overrides + key via env (zero file writes)
xfade opencode glm -- run "fix the bug"       # inline OPENCODE_CONFIG_CONTENT (zero file writes)
xfade aider deepseek --model deepseek-chat
```

Injection is verified for **claude**, **aider**, **codex** (codex-cli 0.155.0)
and **opencode** (1.18.31) — real-machine tested, real config homes stay
untouched. Unregistered presets auto-create; `name --base-url --key` registers
an ad-hoc provider. pi ignores env overrides for custom providers, so pi (and
omp/cline/hermes/openclaw) point at `xfade use`.

### Session view

Proxied conversations get a session identity (opener fingerprint, 30-minute
sticky window, `X-Xfade-Session-Id` response header — no prompt text stored):

```bash
xfade sessions              # list conversations (tool/provider/tokens/status)
xfade sessions show <id>    # one session + its model-switch timeline
xfade stats --by session    # aggregate per session
```

### Smart Fader — intent-aware tiered routing

Off by default; `xfade proxy smart on` enables it (read from the DB per
request, so a running daemon picks it up immediately). Requests are classified
by pure keyword rules — light intents (error triage / tests / static checks /
small refactors) route local-first, heavy intents (big refactors /
architecture) cloud-first, unknown keeps the configured order. Tiers come from
`extra.tier` with a loopback heuristic (Ollama / LM Studio / MLX); within a
tier, providers order by recent health from a 30s-TTL snapshot. Circuit
breakers and failover semantics are unchanged.

Model overrides now also rewrite the `model` field on the chat→chat
passthrough path, so they finally reach local OpenAI-compatible runtimes.

### Project analyzer

Language fingerprint (manifest scan, no parsing) + git pulse, cached in a new
`repo_maps` table. Consumers: `xfade project` (cwd fingerprint + pulse),
`xfade serve` startup prewarm, and the latest repo map in `xfade proxy status`.

## Fixes

- Failover hardening: per-route body cache, conversion skipped on passthrough
  paths, prompt extraction skipped when the fader is off, exact loopback host
  matching (`127.0.0.1.evil.com` no longer matches), `clear_routes` preserves
  `smart_enabled`, word-boundary intent keywords.
- `xfade run` with an official provider + `--model` now injects the
  model-class env var instead of silently dropping it.
- Bare aider model names are prefixed with `openai/` so litellm resolves them
  against the injected base URL.

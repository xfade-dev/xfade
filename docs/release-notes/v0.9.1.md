# xfade v0.9.1

Robustness patch driven by real-machine testing of v0.9.0 — three fixes for failure modes that looked like "xfade hangs".

---

## Fixes

### 429 responses now carry the upstream reason

When every route fails, the proxy used to return a **bare status code** with an
empty body. A `429 budget_exceeded` (or any upstream error) now reaches the
client with the original error body and `Retry-After` header — so instead of
silently retrying an exhausted key, your tool can show you the actual cause.

### Keychain waits are no longer silent

Right after a self-update, the re-signed binary can trigger a macOS Keychain
authorization dialog; if you miss the dialog, the CLI used to hang forever.
Keyring reads now run on a worker thread and, after 3 seconds, print:

```
xfade: waiting on the OS keychain for '<key>' — if an authorization dialog is showing, please allow it
```

The read is never aborted — a slow read is never misreported as a missing key.

### self-update is atomic and symlink-safe

The new binary is staged in the target directory and atomically renamed into
place (no truncate-in-place window). If your `xfade` is a **symlink** (e.g.
`/usr/local/bin/xfade` pointing into a dev `target/release/`), the link itself
is replaced — the link target is left untouched, so `cargo build` and
`self-update` no longer overwrite each other.

## Install

```bash
curl -fsSL https://xfade.sh | sh
# or
brew install xfade-dev/xfade/xfade
# or, from 0.9.0:
xfade self-update
```

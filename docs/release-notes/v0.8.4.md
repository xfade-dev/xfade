# xfade v0.8.4

One new command — **`xfade run`**: launch a tool against a provider for a single session, without touching any config file. Plus: the one-line installer domain is now live.

---

## New

### `xfade run` — one-off launch without switching

`xfade run <id>` launches the tool's binary with the provider injected through
environment variables only. On-disk configs stay exactly as they are, so your
active setup is preserved — try a provider without committing to it:

```bash
xfade run kimi            # launch claude against kimi for this session only
xfade run kimi -- --print # everything after `--` goes to the tool itself
```

- Supported for env-driven tools: **claude** (`ANTHROPIC_BASE_URL` /
  `ANTHROPIC_AUTH_TOKEN` / model vars, per-slot included) and **aider**
  (`AIDER_OPENAI_API_KEY` / `AIDER_OPENAI_API_BASE` / `AIDER_MODEL`).
- Config-file tools (codex / opencode / pi / omp / cline / hermes / openclaw)
  get a clear error pointing at `xfade use` instead.
- Official providers launch the tool as-is (no injection).
- The child's exit code is passed through.

### One-line installer is live

`https://xfade.sh` is now serving the installer end-to-end (Cloudflare edge
redirect → GitHub raw). This is the same command the README has always shown:

```bash
curl -fsSL https://xfade.sh | sh
```

Pin a version with `XFADE_VERSION=v0.8.3`.

## Fixes

- **Windows**: `xfade run` resolves npm-style `.cmd`/`.bat` shims by probing
  `PATH` + `PATHEXT` — Windows' `CreateProcess` only resolves `.exe`, so
  `claude` installed through npm would otherwise not be found.
- **Claude env contract dedup**: `xfade use` (settings.json) and `xfade run`
  (process env) now share a single implementation of the `ANTHROPIC_*`
  contract — `/v1` stripping, per-slot `ANTHROPIC_DEFAULT_*_MODEL` precedence —
  so the two paths can't drift. `xfade use` also clears stale per-slot vars
  from a previously active provider before inserting.

## Install

```bash
curl -fsSL https://xfade.sh | sh
# or
brew install xfade-dev/xfade/xfade
```

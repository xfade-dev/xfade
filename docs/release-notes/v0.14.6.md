# xfade v0.14.6

**Release Focus**: Harden streaming reliability against mid-stream `upstream connection lost mid-stream` errors by raising the default stream idle timeout, injecting downstream SSE keepalives, and logging interruption causes.

---

## What's New in v0.14.6

### Streaming Resilience & Diagnostics
- **Root-Cause Logging**: `make_robust_stream` now logs whether a post-commit interruption was caused by an upstream read error (`upstream stream read error`) or chunk idle timeout (`upstream stream idle timeout after <ms>ms`) to `serve.log`, while preserving client-visible `xfade_stream_interrupted` payloads.
- **60s Default Idle Timeout**: Raised `DEFAULT_IDLE_TIMEOUT_SECS` from `15s` to `60s` so long thinking or tool-call pauses on upstreams without periodic SSE keepalives (such as Bedrock relays) do not falsely trigger mid-stream aborts.
- **Downstream SSE Keepalive**: Added a `10s` SSE keepalive wrapper (`event: ping` for `/v1/messages`, `: keepalive` for Chat/Responses) outside `make_robust_stream` so downstream clients (like Claude Code) do not time out while waiting on silent upstreams, without resetting the upstream idle detector or polluting usage extraction.

### Configuration & TUI Parity
- **Configurable `idle_timeout_secs`**: Added `idle_timeout_secs` to `config.json`, `Core::set_idle_timeout_secs`, `xfade config set idle_timeout_secs <secs|default>`, and the TUI `Config` form (`Idle (s)`).

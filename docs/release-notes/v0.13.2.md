# xfade v0.13.2

**Release Focus**: Fix repeated macOS Keychain authorization dialogs during TUI model probing and `xfade doctor --security --fix`.

---

## What's New in v0.13.2

### macOS Keychain ACL & Prompt Fixes
- **Real ACL Reset on macOS**: `set_password_macos_allow_all` now deletes any existing Keychain item before recreating it with `add-generic-password ... -T ""` (with automatic fallback restoration on error), ensuring existing items actually receive the `allow-all` ACL instead of keeping their old restricted ACL via `-U`.
- **Immediate Abort on Keyring Denial/Error**:
  - `xfade doctor --security --fix` now covers all non-official providers (active/routed first) and stops immediately if the user denies/cancels a Keychain prompt instead of prompting for every remaining provider.
  - `Core::resolve_probe_params` no longer falls back to `global_api_key()` on `CoreError::Keyring`, and TUI model probing (`p`) runs keyring lookups on a background thread that aborts the batch on the first keyring error while suppressing stderr hints on the alternate screen.
  - Legacy `agent-switch/` migration also stops on the first keyring error.

# xfade v0.10.1

One catalog, every provider. This release lets AI coding tools see and pick models from all your upstreams at once, then routes the chosen model back to the provider that owns it.

---

## Aggregated model catalog (`models-merge`)

`GET /v1/models` used to return only the first successful upstream's catalog. With a local gateway (15 models) and a cloud router (536 models, zero overlap), your tools only ever saw 15.

Opt in:

```bash
xfade proxy use freebuff omni --target chat
xfade proxy models-merge on
curl http://127.0.0.1:24860/v1/models
```

- Fans out to every configured route concurrently (5s probe timeout), skipping circuit-open providers; probes never mutate the circuit breaker that governs chat traffic.
- Raw model ids stay unchanged when unambiguous; ids exposed by 2+ routes are namespaced `<route_id>/<model>` (the ambiguous raw id is hidden).
- Persists a `model → owning route` map, so a POST naming a model is pinned to its owner and forwards the real upstream id — no prefix guessing.
- Off by default: with the toggle off, GET and POST are byte-for-byte unchanged.
- Zero-success degrades to the old first-success forward and keeps the last-known map.

`xfade proxy status` prints `models merge: on|off`; `/__xfade/status` exposes `models_merge`.

## Compatibility

Guarded `ALTER TABLE` adds `models_merge` + `model_routes`. The GUI's legacy `set_routes` stays column-scoped (no GUI changes); route writers clear the cached map while every independent toggle survives `proxy use` / `proxy clear`.

## Install

```bash
curl -fsSL https://xfade.sh | sh
# or
brew install xfade-dev/xfade/xfade
```

# xfade v0.13.0

**Release Focus**: Model probing, model alias mapping, multi-route management in `xfade tui`, and automatic daemon version handshakes across upgrades.

---

## What's New in v0.13.0

### 1. Model Probing (`p`)
- Press `p` in `xfade tui` to query `/v1/models` across all configured custom providers concurrently in background threads.
- Provider details display a `Catalog` row with probing spinner, discovered model count/preview, or error state.
- Add/Edit `Model` fields automatically offer `←/→` candidate cycling from probed models while still allowing custom typed names.

### 2. Model Map Configuration (`m`)
- Press `m` to manage alias mappings (`alias -> provider=upstream_model`) and toggle `models-merge` (`Space`) directly in the TUI.
- Supports adding (`a`), editing (`e` / `Enter`), and removing (`d`) rules, with provider cycling (`*` or configured providers) and probed upstream model suggestions.

### 3. Multi-Route & Per-Route Model Binding (`r`)
- Press `r` to manage proxy routes without leaving the TUI:
  - `Space`: toggle route enabled/disabled
  - `K` / `+` and `J` / `-`: reorder failover priority
  - `e` / `m`: bind a per-route model override (with `←/→` probed model cycling)
  - `Enter`: save routes and model bindings

### 4. Upgrade & Daemon Lifecycle
- `/health` and `/__xfade/status` report the running daemon version; CLI commands detect version mismatches and automatically restart the daemon (`launchctl kickstart -k` / `systemctl --user restart`).
- `xfade serve restart` subcommand for manual restarts; `xfade doctor` checks Homebrew symlinks and daemon/CLI version alignment.
- `xfade self-update` guards Homebrew-managed installs and directs users to `brew upgrade`.

---

## Upgrade Instructions

### Homebrew (macOS & Linux)
```bash
brew update && brew upgrade xfade-dev/xfade/xfade
```

### One-Line Script
```bash
curl -fsSL https://xfade.sh | sh
```

### Self-Update
```bash
xfade self-update
```

# xfade v0.14.1

**Release Focus**: Fix false `502 ttft_timeout` errors on large-context requests by raising the default TTFT timeout from 30s to 90s and making it configurable.

---

## What's New in v0.14.1

### Configurable Proxy TTFT Timeout
- **Default Raised to 90s**: `TimeoutConfig::default().ttft_timeout` is raised from `30s` to `90s` (`DEFAULT_TTFT_TIMEOUT_SECS`) so large-context prefill requests (e.g. 30k+ tokens) do not falsely time out during upstream latency spikes and trigger circuit-breaker cooldowns.
- **Persistent Config (`config.json`)**: Added `ttft_timeout_secs` to `Config` and `TimeoutConfig::from_config`. Configure via `xfade config set ttft_timeout_secs <secs>` (or `default` to reset), then `xfade serve restart`.
- **CLI Override**: Added `xfade serve --ttft-timeout <secs>` for foreground proxy runs.

## Upgrade Instructions

### Homebrew (macOS & Linux)
```bash
brew update && brew upgrade xfade-dev/xfade/xfade
```

### One-Line Script
```bash
curl -fsSL https://xfade.sh | sh
```

### Self-Update
```bash
xfade self-update
```

> **Note**: After upgrading, run `xfade serve restart` so the running daemon picks up the new binary.

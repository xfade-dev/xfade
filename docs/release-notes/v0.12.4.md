# xfade v0.12.4

**Release Focus**: The gateway never gets stuck rejecting a provider after a probe.

A subtle circuit-breaker bug could leave a HalfOpen probe slot held forever. The result was a provider that worked fine in isolation but was permanently rejected by the gateway with `503 no usable provider` — even after the upstream recovered. This patch makes the probe reservation impossible to leak.

---

## What's New in v0.12.4

### 1. No more stuck `503 no usable provider`
The failover loop admitted a HalfOpen probe and then hit an early `continue`/`return` (missing provider, missing base URL, conversion failure, client disconnect) without ever releasing the probe slot. The slot then stayed held, so every later request skipped that route and returned `503`. The reservation is now wrapped in an RAII guard that releases it on every exit path; explicit success/failure outcomes disarm the guard instead of double-releasing.

### 2. Streaming success can't steal a newer probe
A deferred stream completion used to release the probe slot again, which could clobber a *newer* request's reservation. Streamed success now advances HalfOpen recovery without touching the slot.

### 3. Client disconnects are no longer silent
If a client drops mid-stream, xfade now records the request and closes the session instead of leaving no trace. The upstream is not penalized — it already committed before the disconnect.

### 4. Dependency hardening
Bumped `cookie` to 0.18.3 (RUSTSEC-2026-0594).

### Homebrew (macOS & Linux)
```bash
brew update && brew upgrade xfade-dev/xfade/xfade
```

```bash
curl -fsSL https://xfade.sh | sh
```

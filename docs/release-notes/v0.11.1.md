# xfade v0.11.1

Dependency security update. **Upgrade from v0.11.0**: its binaries were built
with TLS, runtime and SQLite crates that have published advisories.

---

## Security

- TLS stack: `rustls` 0.23.42 → 0.23.46 (RUSTSEC-2026-0285, -0346, -0348,
  -0349), `rustls-webpki` 0.103.13 → 0.103.17 (RUSTSEC-2026-0382), and
  `webpki-roots` 1.0.9 → 1.0.12 (RUSTSEC-2026-0381: removes a root that allowed
  distrusted emSign intermediates).
- `tokio` 1.53.1 → 1.54.1 (RUSTSEC-2026-0386) and `rustix` 1.1.4 → 1.1.6
  (RUSTSEC-2026-0486).
- Bundled SQLite 3.54 via `rusqlite` 0.41 (RUSTSEC-2026-0459 / CVE-2026-119375).
- `ratatui` 0.30 / `crossterm` 0.29 (fixes `lru` unsoundness, drops `paste`).

## Supply chain

- `cargo-deny` (advisories incl. unsound/unmaintained/yanked, licenses,
  sources) is now a required CI check and also runs daily. Every exception in
  `deny.toml` records a reason.
- Each release publishes `xfade.cdx.json`, a CycloneDX 1.5 SBOM of the CLI
  limited to crates in its real build graph. It is listed in `SHA256SUMS`, so
  it is covered by the Sigstore signature and the build-provenance attestation.

Verify a downloaded CLI archive:

```bash
scripts/verify-release.sh v0.11.1
```

## Session handover

- `xfade <tool> --handover` now passes the brief to the tool's initial prompt
  (Claude Code, Codex, OpenCode, Aider) instead of only printing/copying it.
- **Experimental, off by default:** `xfade proxy handover-inject on` prepends
  model-switch context to the next request's final user message. It is never
  written into `system` / `instructions`, is injected once per switch, and is
  marked done only after the upstream accepts the request.
- Known limits: with several active projects, the project root is the most
  recently analyzed one unless a client sends `x-xfade-project-root`; Codex
  starts working on the injected prompt immediately.

## Compatibility

- No configuration or data migration is required. The SQLite file is opened
  by the newer bundled SQLite without changes; a `handover_auto_inject`
  column is added to `proxy_state` on first open.
- Not yet addressed (tracked): the proxy still defaults to no auth token on
  loopback, and adapters still write the upstream API key into client configs.

# xfade v0.14.2

**Release Focus**: Enable in-place provider protocol switching (`xfade edit --protocol`), clarify route protocol status, add prompt-cache token observability to `xfade stats`, and forward `anthropic-beta` headers for native Anthropic `/v1/messages` upstreams.

---

## What's New in v0.14.2

### Protocol Management & Passthrough
- **In-Place Protocol Editing**: Added `--protocol <chat|messages|responses>` to `xfade edit`, allowing provider wire protocols to be switched without re-adding the provider or overwriting its stored API key.
- **Route Protocol Visibility**: `xfade proxy status` now displays per-route `protocols:` (`<id>=<protocol>`), and `xfade proxy use --target` is marked deprecated in favor of `xfade edit --protocol`.
- **`anthropic-beta` Header Passthrough**: Client `anthropic-beta` headers (e.g. 1M context, interleaved thinking) are now forwarded when targeting Anthropic `/v1/messages` upstreams, while continuing to be stripped for non-Anthropic upstreams.

### Cache Hit Observability
- **Request Logs & Migration**: `request_logs` now persists `cached_prompt_tokens` and `cache_write_tokens` (with automatic `ALTER TABLE` migration for existing databases).
- **CLI Stats**: `xfade stats` now displays `cache_read` and `cache_write` token columns.

## Upgrade Instructions

### Homebrew (macOS & Linux)
```bash
brew update && brew upgrade xfade-dev/xfade/xfade
```

### One-Line Script
```bash
curl -fsSL https://xfade.sh | sh
```

### Self-Update
```bash
xfade self-update
```

> **Note**: After upgrading, run `xfade serve restart` so the running daemon picks up the new binary.

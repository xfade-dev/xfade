# xfade v0.14.9

**Release Focus**: Fix `agy` `403 key_model_access_denied` (`model 'https'`) caused by `customModelsConfig` URI embedding, and add a configurable gateway fallback mapping for `agy` interactive title-generation requests.

---

## What's New in v0.14.9

### Antigravity CLI (`agy`) `modelName` Fix
- **Bare `modelName` in `customModelsConfig`**: Updated `agy_custom_models_config` to emit `"modelName": "<model>"` instead of `"gemini-api://<base>/models/<model>"`. `agy` uses `GOOGLE_GEMINI_BASE_URL` for the endpoint and previously misparsed the embedded URL scheme (`https`) as the model name on custom model keys.
- **Backward-Compatible `read_current`**: `AgyAdapter::read_current` now parses bare model IDs, `models/<id>`, and legacy `gemini-api://<base>/models/<model>` entries.
- **CLI Usage Hint**: `xfade use <name> --tool agy` now reminds users to launch third-party providers with `xfade agy <name>` or `xfade run <name> --tool agy`.

### Gateway Default Fallback Mapping for `agy`
- **Title-Model Fallback**: Added `default_gateway_model_fallback` in `forward.rs` to map `gemini-3.1-flash-lite-preview` → `gemini-3.8-flash` on `agy` / `/v1beta` requests when no explicit `model_mappings`, `route_models`, or `model_override` is set.
- **User-Overridable**: Explicit `xfade model-map set gemini-3.1-flash-lite-preview "*" <upstream_model>` mappings always take precedence.
